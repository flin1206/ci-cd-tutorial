# CI/CD 完全入門教學

> 用「工廠生產線」和「自動販賣機」的比喻,帶你從零開始搞懂 CI/CD。
> 就算完全沒寫過程式,只要看得懂日常生活中的流程比喻,也能跟著這份教學一步步理解。

---

## 這是什麼?

這是一份**免費、開源**的 CI/CD(持續整合/持續交付與部署)教學專案。

裡面不只有文字說明,還有**真的可以在這個 repo 裡面自動跑起來**的範例:

- 每次有人推程式碼上來,GitHub 會**自動幫你跑測試**(對應「持續整合 CI」)
- 測試通過後,GitHub 會**自動幫你把網站部署上線**(對應「持續交付/部署 CD」)

你可以到本專案的 [Actions 分頁](../../actions) 親眼看到它們運作的過程。

---

## 為什麼要學這個?

想像你在學校辦園遊會,你們班要賣手搖飲:

- 如果每一杯飲料都要老師「檢查一次配方、檢查一次衛生、檢查一次收銀」,
  那賣 100 杯飲料要花非常多時間,而且很容易漏檢查。
- 但如果你們設計了一套**固定的檢查流程 + 自動化工具**(例如自動秤重機、自動收銀機),
  每一杯飲料都會**自動、一致地**被檢查跟處理,又快又不容易出錯。

寫程式也是一樣的道理。CI/CD 就是幫工程師打造的那一套「自動檢查 + 自動上架」流程。

## 快速開始(3 分鐘感受一下)

1. 打開本專案的 [Actions 分頁](../../actions),你會看到過去每一次自動化執行的紀錄。
2. 點開任何一次紀錄,你會看到像是「安裝套件 → 執行測試 → 部署」這樣一步一步的過程,
   跟看食譜步驟一樣直覺。
3. 打開 [`examples/calculator`](./examples/calculator),試著把裡面的加法函式改錯,
   推上 GitHub 後,你會看到測試自動失敗、並且被標記為「失敗」。
4. 改回正確答案再推一次,你會看到結果變回「成功」,而且網站範例會自動重新部署。

> 不知道「推上 GitHub」是什麼意思?沒關係,這在 [第 2 章](./docs/02-版本控制與Git基礎.md) 會解釋。

## 名詞小抄(先混個眼熟就好,後面章節都會詳細解釋)

| 名詞 | 白話翻譯 |
|------|----------|
| CI(Continuous Integration) | 持續整合:每次改完程式,自動幫你檢查有沒有壞掉 |
| CD(Continuous Delivery/Deployment) | 持續交付/部署:檢查通過後,自動幫你把成果送到使用者手上 |
| Pipeline(管線) | 一連串自動化步驟串起來的流程,像工廠生產線 |
| Workflow | GitHub Actions 裡,一整套自動化流程的名稱 |
| Runner | 實際幫你執行這些步驟的「虛擬電腦」 |
| Job / Step | Workflow 裡的「大工作」與「小步驟」 |
